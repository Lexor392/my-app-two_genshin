# Аудит Genshin Impact Random Lab

**Дата:** 26 октября 2026 г.
**Объём:** полный обзор файлов проекта, основной логики приложения, загрузки данных, интерфейса, доступности, локализации, зависимостей и сборки.
**Режим:** аудит без изменений исходников. В репозитории уже были незакоммиченные изменения после переноса версии из `gh-pages`; они сохранены. Этот отчёт — единственный новый файл текущего аудита.

## Статус работ по аудиту — 26 октября 2026 г.

В результате последующих работ проект переведён с Create React App на Vite, ошибки загрузки и доступности исправлены, а интерфейс получил оформление в стилистике Тейвата. Этот раздел актуализирует исходные рекомендации ниже: они фиксируют состояние проекта на дату аудита и не описывают выполненные позже изменения.

- **Исправлено:** тайм-ауты, повторы и отмена сетевых запросов; кэш API в `sessionStorage`; необязательные локализованные источники; поиск изображения Local Legend только при отсутствии подходящего локального источника.
- **Исправлено:** устаревший счётчик посетителей удалён; подписи источников и дата обновления относятся к каталогу, а не к статической статистике сообщества.
- **Исправлено:** диалог результата получил заголовок, управление фокусом и закрытие клавишей Escape; состояние кнопок фильтра и выбора передаётся через `aria-pressed`; язык документа синхронизируется с настройкой; добавлены стили `:focus-visible` и `prefers-reduced-motion`.
- **Исправлено:** карточки персонажей и боссов сохраняются при недоступности всех изображений и показывают оформленную заглушку. Персонажи расположены от новых релизов к старым. Внутренний скролл списка пула отключён.
- **Исправлено:** рулетки анимируют трек через `requestAnimationFrame` и CSS transform без обновления React-состояния на каждом кадре; кадры и таймеры очищаются при остановке и размонтировании.
- **Исправлено:** Create React App заменён на Vite/Vitest; удалён устаревший `react-scripts`; `README.md` переписан под текущий проект.
- **Проверки:** итоговые `npm test`, `npm run build` и `npm audit` выполняются после завершения правок; CI включён в `.github/workflows/ci.yml`.

Остаётся осознанное ограничение: приложение использует внешний каталог и изображения, поэтому при сетевой недоступности отдельных ресурсов возможны заглушки. Полный офлайн-режим не включён, поскольку в исходном аудите он был условным предложением, а не обязательным поведением.

## Краткий вывод

Проект уже представляет собой полноценное SPA: есть рулетка персонажей и боссов, фильтры и управление пулами, отряд из нескольких персонажей, история результатов, настройки, пять языков и две темы. Визуальный стиль целостный, тёмная бирюзовая палитра, карточки и навигация образуют понятную структуру. Производственная сборка проходит.

Главные риски сейчас — хрупкая загрузка данных из внешних API, устаревающие/неработающие показатели сообщества, крупный монолитный компонент, недостающая доступность диалога и управления, неполное покрытие локализацией и неблагополучное состояние зависимостей. Это не означает, что все пользовательские функции сломаны: часть проблем проявляется только при отказе внешнего сервиса, при использовании клавиатуры/скринридера или при выборе не русского и английского языка.

## Что уже хорошо работает

- **Основной сценарий понятен:** пользователь выбирает этап, настраивает пул, запускает ролл и получает визуально выделенный результат.
- **Полезный набор функций:** карточный и списочный режимы, поиск/фильтры, выбор видимых элементов, несколько дорожек персонажей, сохранение отрядов, повторный ролл и история с фильтрами и удалением.
- **Настройки не декоративные:** язык, светлая/тёмная тема, громкость звуков, эффекты, длительность ролла и лимит истории.
- **Пять каталогов переводов:** русский, английский, китайский, японский и корейский; данные API запрашиваются с локализованными именами.
- **Адаптивность предусмотрена:** в стилях есть отдельные брейкпоинты и мобильное представление рулетки.
- **Сборка проходит:** `npm run build` завершился успешно. Размер основного сжатого JS-бандла около 88 KB, CSS — около 6 KB.
- **Базовое экранное представление проверено локально:** главная панель отображает каталог персонажей и боссов, основные карточки и настройки статистики; пустой пул имеет отдельный текст и действие для перехода к выбору.

## Дизайн и пользовательский опыт

### Сильные стороны

- Единая палитра, карточный стиль и контрастные основные действия создают узнаваемый интерфейс.
- Главная панель показывает масштаб каталога и основные входы в сценарий.
- Фильтры, счётчик выбранного пула и действия выбора/снятия выбора дают пользователю контроль над результатом.
- Настройки собраны по смысловым группам; важные состояния видны на экране.
- Для пустого пула предусмотрено понятное восстановление сценария.

### Что улучшить

1. **Состояние счётчиков:** отделить актуальные данные от статических; всегда показывать дату обновления для статистики сообщества. Если онлайн-сервис недоступен, показывать нейтральный статус без ощущения, что сломана вся страница.
2. **Доступность:** добавить семантическое состояние выбранности, управляемый фокус диалога, закрытие Escape, видимый фокус для всех интерактивных элементов и режим сокращённой анимации.
3. **Мобильные сценарии:** пройти полный путь на узком экране — настройка фильтров, многодорожечный ролл, модальное окно, действия с историей. Визуальная адаптация в CSS есть, но отдельный полный аудит реального поведения на нескольких устройствах не проводился.
4. **Понятность данных:** пояснить, что именно означают суммарные числа сообщества, как часто обновляются и какие данные хранятся только в браузере.
5. **Обратная связь:** проверить загрузку, повторную попытку, пустые результаты, ошибку изображения и недоступность API как отдельные состояния интерфейса.

## Что отсутствует или требует решения

- Автоматические проверки ключевых сценариев: выбор языка/темы, фильтры, сохранение настроек, история, повторный ролл, отряд и отказ API.
- Устойчивая стратегия загрузки: тайм-ауты, частичный результат при сбое одного источника, кэш и внятное восстановление.
- Документация проекта и источников данных вместо шаблонного README.
- Полная локализация динамических подписей и форматов дат на все заявленные языки.
- Явная политика для внешних сервисов и локального хранения настроек/истории. В приложении используются cookies, внешние API и внешние изображения.
- Офлайн-режим — если он является целью продукта; сейчас наличие manifest не означает, что сайт будет доступен без сети.
- Автоматизированная сборка/проверка при изменениях. В корне не обнаружен workflow CI.

## Проверки и границы аудита

- `npm run build`: **успешно**, с предупреждением `no-loop-func` и сообщением об устаревшей базе Browserslist.
- `npm audit`: 61 замечание (10 low, 14 moderate, 34 high, 3 critical); зависимости не обновлялись.
- Визуально проверена локально главная страница и экран пула; онлайн-счётчик в наблюдавшемся запуске показывал «нет данных».
- Тесты не запускались, чтобы аудит не выдавал непроверенные сценарии за проверенные. Автоматизированная проверка скринридером, клавиатурой, контрастности и реальными мобильными устройствами не проводилась.
- Источники каталога и изображений являются внешними и могут менять доступность или формат независимо от кода приложения.
